## 打开应用

需要 **macOS 和 Node.js 22+**，无需安装 npm 依赖，也无需全局安装 Mole。

首次获取项目（同时下载固定版本的 Mole）：

```sh
git clone --recurse-submodules https://github.com/Ray-hola/Minorminor.git
cd Minorminor
```

如果已经克隆但 `vendor/mole/` 为空，运行 `git submodule update --init --recursive`。

在终端中启动浏览器版服务；终端窗口保持打开，按 `Ctrl+C` 停止。`start.command` 现在启动独立的 Rust 桌面版。

也可以在本目录运行：

```sh
npm run web
```

打开 **<http://127.0.0.1:4783>**。端口已占用时运行 `PORT=4784 npm run web`，再访问相应地址。

任一页面的扫描入口都会启动同一项后台同步任务：文件统计 → AI 工具识别 → 项目归类 → 项目占用 → 本机模型列表。完成后一次更新总览、文件分类、磁盘分析和 AI 专项；取消、失败或服务中断会保留上次完整结果。扫描期间可以切换页面或重新打开浏览器查看进度。清理预览和模型判读仍由各自按钮发起。

iCloud / File Provider 目录通过独立进程读取；连续 10 秒没有返回数据会记录读取超时，保留已读统计并继续其余目录。无法读取的部分会列入错误明细。

## 现在可以做什么

| 页面 | 实际行为 |
| --- | --- |
| 总览 | 读取当前磁盘总量、可用空间，展示扫描入口与统计 |
| 空间清理 | 以占用图、分类、路径和文件清单展示 Mole 候选，勾选后逐文件清理并记录结果；另可把旧日志与安装包移到废纸篓 |
| 磁盘分析 | 后台完整遍历启动磁盘数据卷或整个用户目录，实时展示所有一级目录（含隐藏目录）的占用 |
| 项目清理 | 自动发现普通项目，汇总目录及关联工具文件，按缓存、日志、会话、记忆查看并选择整理 |
| AI 专项 | 统计 AI 工具缓存、模型、会话与配置；缓存接入 Mole 逐项清单，Ollama 模型使用官方接口管理 |
| AI 判读 | 核对元数据后调用指定模型，逐项解释用途、清理代价与不确定之处；另保留明确标识的本地规则建议 |
| Mole 引擎 | `clean` 先原生预览，再确认执行真实用户级清理；`purge`、`installer`、`optimize` 仍仅预览，均展示实时输出 |

页面下方的“逐项整理文件 · 移到废纸篓”只允许选择两个目录中的**直接子文件**：日志目录里超过 14 天的 `.log`、`.log.N`、`.log.gz`、`.log.N.gz`，以及下载目录里超过 7 天的 `.dmg`、`.pkg`。年龄采用修改时间与元数据变更时间中较新的一个。ZIP、文稿、目录、符号链接不进入这个移动计划。缓存使用上方的可视化清理流程。

勾选文件 → 审阅并整理 → 再次核对清单 → 确认移到废纸篓。**移到废纸篓不会立即释放空间**，需要时可在访达里手动移回原目录。文件在废纸篓里带有 `Minorminor-UUID-` 前缀，原位置与新位置记录在本地 `.runtime/cleanup.jsonl`；不承诺 Finder 的“放回原处”功能。

## 清理缓存、日志与残留

在 **空间清理 → 可视化清理** 点击“生成清理清单”：先运行 Mole 原生 `clean --dry-run`，再把本次清单中的具体目录完整展开。可以查看类别占用图、按名称或路径搜索、按类别筛选，查看每个项目的大小、原因与全部文件；文件详情每页 100 条，项目每页 40 条，无总数截断。清单支持导出。默认不勾选任何项目。

勾选需要处理的项目 → “审阅所选清理” → 核对路径、文件数、大小与永久删除说明 → 明确确认。**只删除所选项目中已记录的普通文件，并移除空目录，不会执行整次 `mo clean`，不清空废纸篓。永久删除无法撤回。**

逐项清理范围限于本用户的 `Library/Caches`、`Library/Logs` 子项、npm `_cacache` 子项、pip/uv/go-build 缓存子项、容器 tmp/缓存子项，以及 Application Support 下特定缓存目录或 CrashReporter 文件。每项还必须来自最新成功的 Mole 原生预览。不支持的路径只展示；嵌套项合并到上级，避免重复选择与计数。包含符号链接、其他挂载卷、特殊文件或无法完整读取的项目不能选择。

执行前读取 Mole 原有的路径保护、白名单、模型缓存与活动应用判断（只做安全检查，不调用其删除命令），再复核完整目录清单、inode、大小、mtime、ctime。每个文件删除前再次复核身份和父目录；执行使用非递归的 `unlink` 与 `rmdir`，因此清单之后新增的文件不会被递归删除。文件变化、权限不足、Mole 安全检查未通过或取消时，保留对应项目并记录原因。应用仍可能在最终检查后重新启动或写入；这不是文件系统事务，取消也不会撤回已完成的删除。

完成后，**清理记录**显示每个项目的已删除文件数、保留数、原因及估算占用，可分页查看每个文件和目录的执行状态，并导出完整 JSONL。记录保存在 `.runtime/cleanups/<任务ID>.jsonl`，原始审阅清单在 `.runtime/plans/`，确认记录在 `.runtime/selection-actions.jsonl`。分配大小不等于保证释放的磁盘空间，APFS 快照、克隆与硬链接会影响实际值。执行记录跨正常服务重启保留；可执行清单不跨重启恢复。

### 高级：整次 Mole 原生清理

**Mole 引擎**页面仍保留整次原生清理：先“生成清理预览”，再“审阅并执行清理”。该确认框显示原始输出，并明确说明这是整次清理；与空间清理页面的勾选无关。

整次原生清理按 Mole 当前规则重新检查并**永久删除**符合规则的用户级缓存、日志与残留，可能包含废纸篓。不会申请管理员权限，系统阻止访问的项目仍会跳过。需要控制具体范围时，使用“空间清理 → 可视化清理”；原生整次清理的实际范围可能随文件状态变化。

全盘占用扫描不能授权深度清理。必须有最新一次成功且非空的 Mole `clean --dry-run` 输出；预览 30 分钟有效，只能用于执行一次。失败、被取消、过期或已执行的预览不能启动清理。重新启动服务后必须重新预览。

原生清理的实际结果以输出中的已处理、跳过及错误项目为准；命令结束不代表一定释放了空间。取消不会撤回已经发生的清理。Minorminor 将确认和结果写入 `.runtime/mole-actions.jsonl`，Mole 自己的详细操作日志位于 `~/Library/Logs/mole/`。验证使用临时样例和替代执行器，不自动清理真实用户目录。

## AI 专项与模型判读

左侧 **AI 专项** 可折叠，分为按项目清理、工具概览、目录与缓存、本地模型、读取诊断和 AI 判读六个子页面。扫描结果在子页面之间共享，切换页面不会重新扫描。

扫描自动串联项目发现、工具识别、格式适配、路径补读和占用更新。普通项目通过 Git、Node、Python、Rust、Go、Java、Swift 等项目标记发现，不依赖 AI 会话历史或桌面路径；依赖、运行环境和备份中的清单不当成独立项目。顶层“项目清理”展示全部项目，AI 专项的项目页展示有关联工具的项目。

项目分析使用发现阶段提供的实际工具目录，包含环境变量、应用元数据和专属标记识别出的改名目录。格式适配与目录位置分离；Codex 一个配置目录的索引不会抑制其他目录的会话头补读。关联文件通过通用解析器在所属工具明确的会话 / 归档范围内按唯一完整文件名匹配，支持 gzip 和 zstd 压缩变体，不改写工具数据库，不跨配置目录或跟随链接。读取诊断可按项目、状态和路径筛选，分别列出可读取、已补读、路径失效、权限受限及安全跳过，并显示索引路径与实际路径。压缩会话只在内存中有界解码开头片段；预览仅提取目录、标题、时间与记录类型，不展示会话正文。

`vm-bundle`、`vm_bundles`、虚拟机实例与常见虚拟磁盘按运行环境识别，说明系统镜像、启动资源和实例磁盘的用途。实例可能保存工作文件，默认保留；包含此类资源的缓存父目录也不能通过可视化清理清单删除。

在 **AI 专项** 选择扫描范围并点击“开始扫描”或“重新扫描”，后台自动完成工具识别、目录统计、项目归类与项目大小更新，无需再分别更新项目和占用。支持 OpenCode、Pi、Grok、Grok Bot、Hermes、Comate，以及 Claude / Claude Code、Codex、Cursor、Windsurf、Trae、Gemini / Antigravity、Continue、Kimi Code、Qwen Code、Kiro、Goose、Aider、Amp、OpenClaw、CodeBuddy、WorkBuddy、Qoder / Qoder CN、CodeArts、DeepSeek dsh、Serena、Ducc / Baidu CC、DuMate / 千帆、ima、Browser Use 等工具和模型组件。并不据此宣称能识别所有 agent。

发现线索包括标准目录、专属文件组合、项目配置、已安装应用的 bundle ID / package.json / product.json / ASAR 根包信息，以及 PATH 中的已知命令入口。对已安装 npm / pnpm 包、应用内 ASAR、IDE 扩展和 uv / pipx / Hermes Python 环境核对实际安装清单；Agent SDK 和内嵌 CLI 展示宿主、版本、身份与位置，不能只凭依赖声明就认定安装。编译后的内嵌命令入口标明宿主、未核验版本与中等置信度；不将命令名匹配伪装成已核验包身份。只读取安装包元数据的必要字段，不执行 agent 命令，不读取会话、账号配置、密钥或模型正文。通用 AGENTS.md、CLAUDE.md、SKILL.md 不能单独证明某种 agent 已安装。

| 工具 | 主要新增线索 |
| --- | --- |
| OpenCode | 配置、XDG 缓存、数据 / 状态目录，opencode.db、项目 opencode.json / jsonc 与 .opencode 资源，桌面安装包标识 |
| Pi | ~/.pi/agent、深层项目 .pi 配置与扩展资源、PI_CODING_AGENT_DIR / SESSION_DIR、安装包 piConfig.configDir 与命令入口；核对 npm / pnpm、宿主依赖与 ASAR 内嵌的 Pi 包；组件单独标识，不等同于独立安装 |
| Grok / Grok Bot | config.toml + agent_id + active_sessions.json 组合，以及 .grokbot-data-root-v1；两者分别归属 |
| Hermes | config.yaml + SOUL.md + state.db 组合、HERMES_HOME、桌面应用与标准数据目录 |
| Comate | .baidu-cx + ctrl-servers.json 组合、应用 product.json 的 dataFolderName、.comate-engine 与桌面缓存 |

项目发现遍历整个用户目录，没有深度、条数或时间截断。Library 使用应用数据索引；node_modules、vendor、版本库、虚拟环境、应用运行输出和已识别数据根目录不继续用于项目发现，页面展示排除类型及数量。已匹配数据目录的占用统计仍会遍历其全部普通文件。不跟随符号链接，不跨其他挂载卷；硬链接只计一次物理占用，嵌套范围先统计子目录，父项仅计剩余内容。读取错误逐项记录。自定义路径可由专属标记和服务进程实际继承的路径环境变量定位；其他终端独有的环境变量、未知标记或排除目录中的嵌入式 agent 仍可能漏检。

每个工具的“查看识别依据”展示证据路径、匹配方式、置信度和具体数据范围。页面区分“发现数据”“发现安装，未发现数据”“发现 Pi 组件，未确认独立 agent”“未发现本地证据”。未发现不会被表述为未安装，也不会虚构一个目录。Pi 组件必须有实际安装包清单与准确包名，只有依赖声明不算发现安装；内嵌 pi-coding-agent 也不会自动变成独立 Pi 安装。展示组件名称、版本、宿主和完整路径。已知宿主下的普通安装组件计入宿主状态占用并保护，ASAR 内部组件只展示证据，不能当作普通可清理文件。

**“Agent 目录、缓存与日志清单”**逐项列出完整路径、工具归属、用途、占用、文件数、识别依据与保留原因。支持按工具、缓存、日志、安装文件、项目资源、模型和已有清理清单筛选，也可搜索、分页浏览（每页 40 项，无总数截断）并导出全部 CSV / JSON。导出包含本机私人路径，请自行保管。

**项目清理与归类**由同步扫描自动完成本地内容读取和项目归类。读取 Codex、Hermes、WorkBuddy、OpenCode、Grok 的会话 / 项目索引指定字段；识别 Claude、WorkBuddy、Pi 的 JSONL 会话头、Comate / Claude 项目记忆及编辑器 `workspace.json.folder`。以 `cwd` / 工作目录为依据，结合最近的项目清单或已登记根目录归类；同一项目可关联多个 Agent。含安装包清单的备份 / 测试夹具归入外层项目，不将每份测试副本变成一个新项目。找不到的历史目录、用户目录外的临时目录、通用工作区和现存项目分别标记。无法唯一还原的目录编码或缺失 cwd 的记录保留为待确认，不按短名称猜测。

每个项目展示文件路径、会话标题、记忆标题、项目说明摘录及来源；点击“查看文件与归类依据”分页查看全部关联记录。原目录清单的“这是什么”可查看用途、项目关联和日志结构样本。应用通用缓存、模型、安装文件和跨项目索引归入共享资源；共享数据库不按行估算物理占用，也不把项目关联文件大小与父目录快照累加。目录映射不赋予删除权限，仍须原有 Mole 逐文件计划和明确确认。

读取边界公开展示：SQLite 以只读连接按页读取目录、标题及标识字段，不读取消息、工具参数、账号或凭据表；会话头最多前 256 KiB、项目 README / package description 与记忆标题最多前 12 KiB；每个日志范围最多抽读 2 个文件的前 32 KiB，只保留级别、组件、常见错误码和 cwd 引用，不显示原始日志正文。项目说明是来源摘录，不是大模型结论。截断文件数、来源、跳过的链接和读取错误均可查看；未支持格式保留为目录说明或待确认，不能声称已通读全部文件。凭据文件、`.env`、原始消息表、`state.vscdb` 和模型正文不打开，不执行发现的项目代码或文件内指令。内容字段做长度限制和常见凭据脱敏，界面按纯文本转义。

归类任务在服务后台运行，可取消；刷新页面不影响任务，取消不替换上次完成结果。结果保存于私有 `.runtime/latest-state.json`，支持完整 CSV / JSON 导出。新占用快照或清理后旧归类会标记过期。此功能不调用外部模型，也不把摘录加入现有 AI 判读输入；现有模型判读的元数据确认流程保持独立。

**项目占用与按项目整理**：同步扫描自动完成统计，独立 Worker 完整遍历已确认的项目目录及可明确归属的外部 Agent 项目目录、会话和记忆文件。卡片显示已确认分配块占用、目录内 / 工具目录内大小、缓存、日志、会话、记忆与保留的代码 / 依赖 / 配置 / 备份。点击类别可分页查看具体文件和保留原因；按占用或会话数量排序、搜索与跨页勾选项目。子项目先计量，上层目录不重复计入；主目录 / 桌面等通用工作区不重新扫描全部内容，只统计明确关联的 AI 文件。共享数据库连同可读 WAL / SHM、硬链接、跨项目文件单独列出，不能用会话行数分摊物理大小。缺失文件和读错误明确标记，已确认大小不是完整未知部分的零值估计。分类汇总及四类 AI 文件元数据可导出 JSON（不包含全部代码 / 依赖文件索引）。

**逐个展开文件**：点击项目卡片的“展开项目全部文件”，按目录逐层查看代码、依赖、备份等文件；点击缓存、日志、会话、记忆数字卡片，直接展开该类的全部独立文件。每页 100 条，无总数截断，支持文件名 / 路径搜索及大小、名称、修改时间排序。展开一行可查看完整路径、磁盘分配占用、逻辑内容大小、修改时间、用途说明及判断依据。展开项目目录后，独立 Worker 在后台完整统计各层文件夹，显示整体磁盘占用、内容大小、文件数和子文件夹数；统计期间显示进度，可以停止、离开页面或刷新后继续查看，完成后按真实占用排序。统计覆盖全部目录，不限于当前一页；进入子目录复用结果，可手动“刷新文件夹大小”。文件夹占用按内部普通文件的分配块累加，包含全部下层目录（包括独立子项目），父子目录不能重复相加；硬链接在各个目录树内按文件身份去重，兄弟目录里的共享硬链接不能简单相加。符号链接、跨卷和特殊文件不计入，无法完整读取标为“≥ 已确认大小”。目录视图与项目卡片的归类口径不同，后者还涉及外部会话和独立子项目。独立子项目可跳转到自己的清单。通用工作区和缺失目录仅展示已关联 AI 文件。

“读取内容片段，确认是什么”按需在本机读取前 32 KiB，最多展示 4,000 字符。JSON 仅展示名称、标题、说明、版本、类型和工作目录字段；JSONL 仅展示记录类型、角色、标题、工作目录和时间，不展示对话正文或工具参数。已识别的凭据路径、数据库、模型、压缩包和二进制不展示正文；普通文本片段会遮盖常见凭据，但这不等于识别所有敏感信息。每处说明区分路径 / 格式推断与实际读取片段，截断和无法读取均明确标注。片段不上传、不执行、不持久保存。文件夹大小结果缓存在服务内存中，正常页面刷新可复用，服务重启后重新统计；结果显示统计时间，文件发生外部变化时可手动刷新。浏览接口仅接受已登记项目和服务签发的文件 ID，读取前后复核文件身份，不跟随符号链接、不跨卷；查看不会扩大清理范围。

此入口采用独立的**移到废纸篓**流程：勾选项目 → 选择类别 → 生成具体文件预览 → 查看路径及保留原因 → 在预览中另行勾选项目类别 → 确认移动。默认范围是缓存和日志，预览默认不选中任何可执行类别。仅识别明确的生成缓存目录（例如 `__pycache__`、`.pytest_cache`、`.cache`、`.next/cache`）和运行日志；代码、依赖、版本库、运行输出、凭据、数据库、测试夹具和备份不作为可整理文件。最近 24 小时写入、共享、身份变化或当前占用的文件保留。

用户可单独开启会话 / 记忆审阅，并在最终确认中再次确认历史与记忆影响；只处理明确归属的独立普通文件。数据库管理的会话（即使另有 rollout 文件）与共享数据库逻辑记录保持保护，需在原工具管理；多工作目录会话、归类后变动的文件不能直接移动。项目根目录、共享数据库及其记录不会被移动或拆删。

预览按文件冻结身份（设备、inode、大小、修改与变更时间、硬链接数、父目录身份），30 分钟有效且仅使用一次，不接受请求提供的任意文件路径。执行时缓存 / 日志通过只读 Mole 保护和占用检查，会话 / 记忆另用本机 `lsof` 检查；逐文件再次验证身份和废纸篓路径，再同卷原子移动。只移动已经审阅的普通文件，不递归移动目录、不执行 `mo clean`、不清空废纸篓，后来新建或改变的文件保留。操作并不立即释放磁盘空间；可根据原路径与废纸篓去向手动还原。

完整预览保存在私有 `.runtime/project-plans/`，逐文件移动前意向与最终状态保存在 `.runtime/project-cleanups/`；页面展示结果和原路径 / 废纸篓路径。取消会停止后续移动，未处理文件数量单列。服务中断后不自动继续，`moving` 且无最终记录的文件需按原路径和目标路径核对，不把未知结果当成零移动。重启恢复占用和记录，不恢复清理授权。项目整理不扩大原有 Mole 永久删除入口的允许范围。

清单明确区分：

- **已有清理文件清单**：仅关联当前有效的 Mole 逐文件计划中、位于该范围以内的可选部分。点击审阅后沿用原有文件查看、勾选与确认流程；上级清理范围不会自动变成某个窄目录的授权。
- **候选，当前未授权 / 待生成清单**：按专属目录和文件名识别出的缓存、运行日志，展示全部路径和占用；当前未进入 Mole 计划的路径不提供直接删除，也不伪称可立即释放空间。像 .cache/codex-runtimes 这样的运行依赖属于安装文件，目录名含 cache 也不会自动列为可删除缓存。建议先退出工具、检查用途与正在使用的文件。
- **保留 / 未完整读取**：安装文件、内嵌 CLI / SDK、会话、配置、凭据、模型、项目资源，以及无法完整读取的范围，默认保留。缓存不会靠模型输出或目录名称自动升级为可删除。

缓存和日志分别统计；Electron 的 Data / Default / Partitions 等标准容器内的缓存单独归类。不会把 User、sessions、projects、workspace、secretStorage 等受保护内容递归当成缓存。清单刷新时重新关联计划，过期或已经使用的计划不会继续显示为可清理。

专项区分可重建缓存、需审阅的模型/数据集、默认保留的会话/配置/项目。统计出的总占用不是可释放空间。**AI 工具缓存清理**只显示 Mole 当前清单中属于 AI 工具的缓存，复用相同的身份复核、勾选确认和逐文件执行记录；不会借此扩大允许删除的路径。模型、会话和整个 `~/.codex`、`~/.claude` 等状态根目录不进入通用删除流程。

本机 Ollama 在默认 `127.0.0.1:11434` 运行时，可从其 `/api/tags` 获取具名模型。移除前必须确认本次快照中的模型 ID；服务重新核对名称和 digest，并通过 `/api/ps` 确认没有加载中的同名或同 digest 模型，随后调用官方 `DELETE /api/delete` 并复查。不会直接递归删除 blobs；共享层的释放由 Ollama 管理。预览 30 分钟有效，取消/网络失败后可能需要刷新确认原生操作结果。确认与结果记录在 `.runtime/ai-model-actions.jsonl`。Hugging Face 等其他模型库目前只做占用审阅，不提供直接文件删除。

在 **AI 判读** 或专项页点击“连接模型”：

- **本机 Ollama**：检测默认端口已有的模型，填写实际可用的模型名；不会自动安装 Ollama 或下载模型。模型基础地址只允许本机。
- **兼容接口**：支持 Chat Completions JSON 接口，例如 DeepSeek；填写基础 URL、模型名、API Key。云端仅允许 HTTPS，也可使用本机 HTTP 兼容服务。配置保存仅表示已配置，是否可用以实际调用结果为准。

连接地址和模型名保存在 `.runtime/ai-settings.json`；**API Key 只保留在当前服务内存中，不写入配置、审计日志、返回值或浏览器存储，重启后需重新输入**。不会读取其他应用的账号凭据。当前没有遥测。

选择“AI 工具专项占用”或“当前可视化清理清单”，点击“审阅并开始 AI 判读”，查看即将发送的完整输入与目标接口，再明确确认。每批最多 20 项，可继续判读下一批；展示已判读数量、总量，并支持导出全部建议。输入只有名称、`~/` 相对路径、类型、大小、计数、修改时间与规则原因，不发送文件正文、会话、环境变量或系统凭据。云端接口会收到这些元数据。

模型只能给出“建议保留 / 需要审阅 / 可考虑清理”及风险、理由和不确定之处。响应必须是已知 ID 的有效 JSON，未知 ID、重复或无效建议拒绝采用；缺失项目按需审阅处理。受保护项目不能通过模型输出变成可删除项目。**不会自动勾选或删除，不赋予模型文件系统和命令执行工具。** 连接失败、超时、取消或响应不合法均显示失败；规则建议不伪装成大模型结果。

## 与 Mole 的关系

`vendor/mole/` 以 Git 子模块保存上游源码，固定至 [UPSTREAM.json](../UPSTREAM.json) 中的提交，保留原始文档与许可证，没有修改上游代码。克隆时使用 `--recurse-submodules` 即可取得完整源码。网页在本地通过子进程调用这份源码，不依赖已安装的 `mo`。

Mole 原生预览与界面的后台完整扫描分别用于识别清理候选和统计目录占用。可视化清理基于原生预览和单独生成的完整文件清单；全盘占用不作为删除依据。此版本不提供 Mole 的全部 TUI 功能，也没有实现卸载、管理员清理或原生维护执行。

上游采用 **GNU GPL v3**，见 [Mole 许可证](https://github.com/tw93/Mole/blob/6650d0958282aa8052cd2bfeee15f67b17fe613b/LICENSE)。保留其版权与授权信息；新增 Web UI 尚未单独选择发布许可证。内置 IBM Plex 字体沿用 [SIL Open Font License 1.1](../public/fonts/OFL.txt)。当前为开发原型。Minorminor 与 Mole 官方应用无隶属关系。

## 隐私与边界

- 服务只监听 `127.0.0.1`，验证 Host、Origin 与写请求的会话令牌，不提供跨站访问。
- 磁盘 / 占用扫描读取文件名、元数据、目录结构和必要安装标识；“按项目看”另外在本地读取上述指定字段与内容片段，不通读全部正文，没有遥测。AI 判读只有在配置连接、审阅并确认输入后才发送元数据给指定模型服务，项目内容摘录不会发送。
- 后台扫描不设文件数、目录深度或运行时长上限，通过流式目录遍历和最多 16 个并发元数据请求控制资源使用；不读取文件正文。
- 默认扫描启动磁盘数据卷（现代 macOS 的 `/System/Volumes/Data`，界面显示为 `/`），覆盖其中的应用、资源库、用户与隐藏目录；不包含只读系统卷、其他挂载卷或符号链接指向的外部内容。也可选择整个当前用户目录。
- 不跟随符号链接，不跨挂载卷；相同目录身份不重复遍历，硬链接只计一次分配块数。系统拒绝访问、路径消失等错误逐项保存在 `.runtime/scans/<任务ID>.errors.jsonl`，可从界面分页查看全部记录。页面只保留前 100 条错误样本，扫描与完整错误日志没有这个条数上限。
- 扫描运行在独立 Node Worker 中，主服务继续响应页面请求；展示文件数、目录数、已统计大小、实际耗时和当前路径。总量未知时使用活动条，不编造百分比。
- 页面刷新、切换或关闭不影响后台任务；本地 Node 服务需保持运行。支持取消并保留已经读到的统计，取消后的结果不能授权文件移动。若文件系统调用停滞，取消 1.5 秒后会终止扫描 Worker；此时保留任务最后的进度，而不把旧结果标成新扫描结果。
- 每次只运行一个扫描或清理任务。预览强制 `--dry-run` 和 `MOLE_DRY_RUN=1`；真实执行仅允许 `clean`，由服务端校验成功预览、确认标识、时效和一次性使用状态，再以 `MOLE_DRY_RUN=0` 启动。两种模式均以 `MOLE_TEST_NO_AUTH=1` 关闭管理员认证。`clean` 预览及执行不设整体时长上限，支持手动停止；其余预览仍有 3 分钟上限。
- Mole 预览仍可能按上游行为在 `~/.config/mole` 写入预览清单。这不是完全无写入的沙盒。
- 文件移动需要本次扫描的文件 ID 和确认标识；超过 10 分钟必须重新扫描。移动前检查路径、类型、inode、大小与修改时间；发生变化的文件保留并报告原因。
- 不使用 `sudo`。旧日志和安装包的整理移到废纸篓；可视化清理永久删除明确勾选、已审阅的缓存和日志文件；高级整次 Mole 清理可能清理废纸篓。当前服务按单个本机用户设计，不适合对外网开放或多人共享。
- 磁盘数据来自本机文件系统 API。APFS 共享容器与 macOS“可清除空间”可能使数值和系统设置不同；目录占用按分配块数统计，硬链接和 APFS 克隆也可能影响合计。

## 未知 harness 的自动发现

主流工具保留确定性身份和格式适配；其余工具从真实安装清单、声明的数据位置、目录组合和文件结构生成候选，不需要逐个追加产品名称。支持 npm 全局安装、IDE 扩展、Python 安装元数据、macOS 应用元数据，以及无安装信息的本地数据目录。单独的 SDK 依赖或 AGENTS.md 不足以确认独立工具。

候选显示在「AI 专项 → 工具概览」，同时进入目录占用清单。缓存、日志、会话和记忆按通用目录结构拆分计数，全部标明为推断；结构化会话中的唯一显式工作目录可关联项目。未知 SQLite 仅检查表结构，不猜测业务字段、读取消息表或修改数据库；多个工作目录的未知会话不猜测归属。

在模型连接中勾选「扫描后自动识别工具候选」，后续同步自动调用已配置的模型。仅发送安装名称、类别枚举、允许的字段与表结构特征，不发送文件正文、凭据值或项目路径。没有模型、接口失败、缺少证据或 AI 判断为普通软件时，都保留明确状态；可重试未完成候选。判断按本机目录、结构指纹和模型连接缓存 30 天，指纹变化重新分析；不生成或执行模型输出的扫描规则。

未知候选发现使用有边界的抽读：每目录最多 2 个结构化文件，每文件前 16 KiB，每轮最多 4096 个样本；Library 中未知应用数据检查至 3 层，AI 每轮最多 8 批、每批 12 个候选。未抽读数量与读取错误可见，超出批次的候选保留待识别状态。这些边界不截断已发现范围的磁盘占用统计。加密、私有二进制、自定义位置或格式仍可能无法识别；当前没有多台真实 Mac 的完整性或性能验证。

AI 判断只增加用途解释，不能新增路径、改写项目归属或增加删除资格。缓存与日志仍须通过具体清单预览及执行前检查，会话与记忆沿用按项目预览、勾选和确认；不自动选择或清理。

## AI 分析与 AI 总结的权限

「AI 分析 / AI 判读」仅接收元数据与结构特征，文档读取权限固定禁用，配置接口无法开启。模型没有文件工具；返回 tool/function 调用、结构化读取或授权请求时直接拒绝，文字中的索取正文请求改为“权限已禁用 / 证据不足”。本地扫描程序提取结构特征不向模型发送正文。

项目文件与文件夹、项目根目录、Agent 数据范围、候选、磁盘目录及可视化清理清单均有「AI 总结」入口。先在本机准备点选范围，展示路径、内容文件清单、目标接口与模型；点击「发送所选内容并总结」才调用模型。总结使用独立接口、一次性预览 ID 与模型连接版本，不接受自由路径或模型追加的读取请求。文件变化、预览过期或连接改变后需重新选择；不会扩大清理权限。

总结支持文本、代码、JSON / JSONL、压缩会话，以及 macOS 原生 PDFKit / textutil 提取的 PDF、Word、RTF、ODT 文本。凭据、数据库、模型和一般二进制只使用元数据；符号链接与跨卷文件不跟随。文件夹最多检查 160 个条目、32 个目录、3 层深度，抽读 12 个文件，每个文本文件前 16 KiB、合计最多 48,000 字符。PDF 最多前 8 页，原生文档输入最多 16 MiB；图像 PDF 无可提取文本时如实标为仅元数据。非全文与无法读取状态保留。

待总结的正文片段只暂存在内存，10 分钟过期、最多 20 份；使用后删除。正文与总结不写入扫描持久化文件；生成的概括在当前服务 / 页面中可查看。总结内容始终视为数据，不执行文档中的指令或打开其链接。
